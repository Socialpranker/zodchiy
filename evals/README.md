# evals — регрессия зодчего

Зодчий требует от чужого кода того, чего до сих пор не требовал от себя: число
должно приходить из скрипта, а скрипт был непроверен. 1603 строки Python, пять
багов найдены руками, и все пять до контрольной группы выглядели как «в коде
чисто». Этот каталог закрывает разрыв.

```bash
python3 evals/run_evals.py            # юнит + frozen + устойчивость
python3 evals/run_evals.py --unit     # только скрипты, без git и без модели, 0.05 с
python3 evals/run_evals.py --frozen   # measure.py на фикстурах против ground truth
python3 evals/run_evals.py --robust   # вырожденные репо: пустой, битый UTF-8, detached HEAD
python3 evals/run_evals.py --perf     # бюджет времени замера
python3 evals/run_evals.py --rebuild  # пересобрать фикстуры принудительно
python3 evals/run_evals.py --trigger  # выкладка кейсов для проверки description
```

Exit 1 при любом расхождении. Гонять **при каждой правке `scripts/*.py`**
и после любой правки `SKILL.md`: адаптеры в `dist/` собраны из него и
сверяются байт в байт (`scripts/build_adapters.py --check`).

## Слои

| Слой | Что ловит | Модель нужна |
|---|---|---|
| юнит (`test_scripts.py`) | резолвер импортов, парсер лога, пороги, Тарьян, калибровка, гейт | нет |
| юнит (`test_entrypoint.py`) | маршруты единой точки входа: подкоманда без маршрута, потерянный код выхода | нет |
| юнит (`test_adapters.py`) | расхождение `dist/` с `SKILL.md`, относительный путь в адаптере, битый TOML | нет |
| юнит (`test_export.py`) | документ по схеме, дрейф колонок `findings.csv`, уровни SARIF, экспорт из брака | нет |
| юнит (`test_publish.py`) | утечка приватного в публичное дерево: имена репозиториев, чужой домашний путь, внутренние документы, битый после санитайза код | нет |
| frozen (`benchmark_corpus.json`) | сквозной прогон `measure.py` на мини-репозиториях против ground truth | нет |
| устойчивость (`--robust`) | вырожденные репозитории: скрипты обязаны отвечать явным полем, а не трассировкой | нет |
| бюджет времени (`--perf`) | регрессия скорости замера (сейчас 0.4 с на фикстуре, 3.2 с на `repo-A`) | нет |
| trigger (`trigger_cases.json`) | срабатывает ли `description` на непрямые формулировки | да, **не прогонялся ни разу** |

## Правило один-к-одному

У каждого кейса `dirty` обязана быть пара `clean` — и наоборот. `run_evals.py`
проверяет это первым делом и падает, если пара исчезла или обе стороны стали
одной полярности. Без пары метрика «скилл нашёл N» не отличима от «нашёл N и
ещё десять ложных»; метод взят у OWASP Benchmark.

| Риск | dirty | clean (ловушка) |
|---|---|---|
| R5 циклы | рантайм-цикл | цикл только через `if TYPE_CHECKING:` |
| R2 / R3 | сцеплены И связаны, но ребро идёт сквозь `__init__.py` | сцеплены и не связаны ничем |
| R5 fan-in | модуль с fan-in 8 и своей логикой | barrel с тем же fan-in — реэкспорт по замыслу |
| R4 churn | 21 правка, 43% багфиксов — боль | 31 правка, 6% багфиксов — точка расширения |
| R1 сложность | одна функция cc=15 | десять простых функций, сумма по файлу 31, максимум по функции 4 |
| R4 устойчивость | за каждой правкой через сутки идёт фикс (`rework_rate` 0.92) | столько же правок и ни одного фикса |
| R2 скорость | одно изменение трогает 6 файлов | столько же коммитов, каждый в одном файле |

Все пять `clean`-кейсов — не гипотезы: ровно эти четыре ложняка v1 уже описаны
в `SKILL.md` как зафиксированный инцидент, но регрессией до сих пор не держались.

**Чего frozen-слой не покрывает.** R4 «случайная сложность» и R6 «искажение
доменной модели» проверяются здесь только числом churn; их суть — суждение, и
она относится к trigger/live-слою, которого пока нет. Так и записано, чтобы
«10/10 сошлось» не читалось как «риски покрыты все».

## Фикстуры

Фикстура — рецепт (`fixtures/specs.py`), а не каталог с `.git`: вложенный
репозиторий внутри `~/.claude` не переживёт ни клона, ни архива, и «история»
молча выродилась бы в один коммит. `fixtures/build.py` собирает мини-репозитории
в `~/.cache/zodchiy-evals/<имя>-<хэш спецификации>`.

Хэш спецификации в имени — чтобы правка рецепта не переиспользовала старый
репозиторий молча. Достроенность помечается файлом `.zodchiy-fixture-complete`
с числом коммитов: прерванная сборка оставляет каталог, который выглядит кэшем
и отдаёт огрызок истории, а прогон на нём зелёный ровно там, где нечего мерить.
Поймано на себе при разработке этого харнесса.

`measure.json` **не кэшируется**: это выход того самого кода, который проверяем.

## Мутационная проверка

Зелёный харнесс, который не умеет краснеть, хуже отсутствующего. Проверено
пятнадцатью мутациями — каждая возвращала `exit 1`:

| Мутация | Кто поймал |
|---|---|
| `splitlines()` вместо `split("\n")` в парсере лога (баг №1) | юнит |
| `from pkg import sub` не резолвится (баги №2, №5) | юнит + 3 frozen-кейса |
| цикломатическая на функцию = сумма по файлу (баг №3) | юнит + frozen |
| barrel не проходится насквозь (баг №4) | **только** frozen |
| `gate_result` переименован в `verdict` (баг №7) | юнит |
| порог боли 0.25 → 0.5 | юнит + frozen |
| порог сцепления 5 → 50 | юнит + 2 frozen-кейса |
| тесты не исключены из containment | юнит |
| `TYPE_CHECKING` не отличается от рантайма | юнит + frozen |
| окно доделки 14 → 999 дней | юнит |
| Уилсон заменён сырой долей | юнит |
| разрыв эпизода 3 → 0 дней | юнит + frozen |
| путь `source` режется наивным `split(".")` | юнит |
| `selfcheck` не проверяет `source` | юнит |
| `touch_cost` не исключает мега-коммит | юнит |

Строка «только frozen» — довод против соблазна ограничиться юнит-слоем.
Повторить: `python3 evals/run_evals.py` после точечной правки скрипта.

## Trigger-слой

Не прогонялся. Прогон требует модели и делается субагентами: по одному запросу
на агента, у агента есть список скиллов и НЕТ подсказки, какой ожидается.
Считается доля совпадений отдельно по `train` (на них правится `description`) и
по `test` (по ним меряется, не подглядывая) — 60/40 по рецепту `skill-creator`.

Половина should-кейсов намеренно не содержит слов «архитектура» и «техдолг»:
описание, которое ловит только прямые формулировки, на живом разговоре молчит,
а именно так задачу и ставят («боимся трогать модуль оплаты»).

## Известный пробел

`FIX_RE` в `behavior.py` начинается с `^\s*fix` без границы слова — субъект
«fixture: …» или «fixup! …» будет посчитан багфиксом и завысит `fix_share`,
а по нему гейт считает `painful_files`. Цена измерена на калибровочной паре:
0 ложных из 215 совпадений в `repo-A` и `repo-B`. Поэтому не тронуто —
но и тестом не закреплено, чтобы тест не узаконил дефект.
