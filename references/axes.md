# axes — три оси и правила расхождений

Термины и правило допуска — §2, §8 SPEC.md. Поля JSON — реальный вывод
`scripts/behavior.py` и `scripts/structure.py`, не выдуманы отдельно от кода.

## 1. Что даёт каждая ось

| Ось | Чем берётся | Поле JSON | Отвечает на | Принципиально НЕ видит |
|---|---|---|---|---|
| **Намерение** (`intent`) | ADR, CLAUDE.md, README, import-linter (exit code прогона), ArchUnit-тесты (статус), eslint-boundaries (нарушения), `.zodchiy/config.yaml` | нет своего скрипта — читается моделью на фазе `map`, метится `OBSERVED`/`INFERRED` (§4 artifacts.md) | чем архитектура себя объявила | реальное поведение и его дрейф от декларации; частоту изменений; фактическую связанность |
| **Структура** (`structure`) | `structure.py` — граф импортов (tree-sitter или regex-fallback) | `cycles`, `cycles_type_only`, `fan_in_top`, `hubs[].fan_in/fan_out`, `complex_files[].cyclomatic`, `layers`, `external_deps_top` | какая архитектура по форме | связи, которых нет в статическом графе импортов: DI-контейнер, реестр по строковому ключу, рефлексию, dynamic import, event bus, plugin discovery — там нет import-эджа, граф этого не увидит вообще |
| **Поведение** (`behavior`) | `behavior.py` — git log | `temporal_coupling[].degree`, `hotspots[].fix_share`, `containment.ratio`, `knowledge_risk`, `reverts` | чего архитектура стоит на практике | код без истории (`available: false` при `commits_with_code` < `thresholds.min_commits`=60); форму самого кода — только динамику правок; архитектурно верный, но нетронутый код |

## 2. Таблица допуска (§2 SPEC)

| Сошлось осей | `confidence` | Что с этим делают |
|---|---|---|
| 1 | `hypothesis` | в отчёт не идёт; живёт в леджере, ждёт следующего прогона |
| 2 | `finding` | идёт в отчёт с указанием недостающей оси |
| 3 | `verdict` | идёт в отчёт первым, годится в основание для ADR |

Структурный цикл без поведенческой цены — `hypothesis`, не находка.

## 3. Асимметрия осей

**Поведенческая молчит про новый код.** `behavior.py` меряет то, что реально
менялось. Модуль без истории даёт `available: false` целиком (порог
`min_commits`) или просто не попадает ни в `hotspots`, ни в `temporal_coupling`
— не потому что там нет проблем, а потому что метрика по определению не может
их увидеть. `verdict` для такого кода невозможен в принципе, а не маловероятен.

**Структурная не видит рантайм-связей через DI/реестры/рефлексию.** Граф
строится из статических import-выражений (`imports_via_ts` / `IMPORT_RE`).
Связь, которая устанавливается по строковому ключу в конфиге, через
DI-контейнер, реестр обработчиков или `importlib` по вычисленному имени, не
создаёт ребра ни в `graph`, ни в `graph_all` — она для этой оси не существует,
хотя исполняется каждый запрос.

**Ось намерения врёт, когда документы устарели.** ADR «мы отказались от X»
или `current-state.md` прошлого прогона — свидетельство того, что решили, не
факт о том, что исполняется (§3 artifacts.md). Устаревший документ не просто
«неполон» — он активно вводит в заблуждение, если принять его за код.

## 4. Каталог типовых расхождений

| Намерение | Структура | Поведение | Расхождение | Что значит |
|---|---|---|---|---|
| Слои объявлены, import-linter в CI зелёный | Зависимости идут внутрь, `cycles` пуст | domain и его репозиторий встречаются в паре `temporal_coupling` с `degree ≈ 0.92` | **Шов номинальный**¹ | граница соблюдена формально, но реальная линия изменения проходит не по ней — сам слой не является единицей правки |
| Молчит | Пара файлов в `cycles` (size ≥ 2) | Та же пара не проходит пороги `coupling_min_shared`/`coupling_min_degree` — нет общих коммитов | **Мёртвая связь** | цикл существует по форме, ничего не заставляет менять оба файла синхронно — риск потенциальный, не текущий |
| Молчит | Ребра между A и B нет ни в `graph`, ни в `graph_all` | Пара A/B есть в `temporal_coupling` с `degree ≥ 0.45` | **Скрытая связь / дублированное решение** | R3: одно решение в двух местах, либо связь идёт в обход импортов (общая БД, конфиг, копипаста) — линтер её не увидит никогда |
| Молчит | Файл в `hotspots` с высоким `score` (churn × loc) | `fix_share < 0.15` | **Точка расширения, не долг** | правки частые, но не багофиксные — фича растёт, не гниёт; не флагать как «грязный код» |
| Молчит | Файл в `complex_files` с высоким `cyclomatic` | Файл почти не встречается в `commits_with_code`, `edits` малы | **«Рефакторь, когда тронешь»** | холодная сложность — ROI ремонта сейчас отрицательный; порог фиксируется на будущее, не сейчас |
| `current-state.md`/ADR описывает модуль X | X отсутствует в `collect_files`/графе | н/д (истории на несуществующий путь не бывает) | **Документ-призрак** | намерение устарело буквально — модуля физически нет, документ вводит в заблуждение |
| Линтер запрещает связь A→B, правило соблюдается | Ребра A→B нет, структура подтверждает запрет | A и B сцеплены высоким `degree` | **Периметр с дырой** | интеграция идёт не через импорт (общая таблица БД, HTTP-вызов, очередь) — CI видит только import-граф и никогда не поймает этот канал |
| Молчит | Высокий `fan_in` (`hubs`/`fan_in_top`) | `knowledge_risk`: один автор, `share > 0.85`, `edits ≥ 8` | **Bus factor на хабе** | структурно критичный узел (много потребителей) держится знанием одного человека — риск виден только на пересечении осей |
| ADR: «отказались от синхронного вызова X» (§3 artifacts.md) | Граф всё ещё содержит edge к клиенту X | Файл клиента X в `hotspots`/`temporal_coupling` с вызывающим | **Дрейф намерения** | документ и код разошлись; фиксируется как факт, не решается молча в пользу одного |
| Молчит про новый модуль | Модуль в графе, `fan_in`/`fan_out` в норме | `behavior.available: false` либо модуль просто не набрал `min_commits` | **Слепая зона поведенческой оси** | не расхождение по существу, а ограничение метода — максимум `hypothesis` по двум осям, `verdict` здесь невозможен в принципе |

¹ **Проверенный случай.** На живом коде: `import-linter` зелёный, `structure.py`
подтверждает однонаправленные `edges` внутрь слоя, `cycles: []`. При этом
`behavior.py` показывает пару domain-модель / её репозиторий с
`temporal_coupling[].degree ≈ 0.92` — 92% совместных правок. Все три
инструмента порознь сказали бы «граница в порядке». Схождение с поведенческой
осью показывает обратное: граница проведена по слою, а изменение проходит по
фиче, которая режет оба слоя сразу. Это ровно `containment.ratio` низкий для
этой пары при формально соблюдённых импортах.

## 5. Поля JSON без отдельного описания

Реальные выходы скриптов шире таблиц §1 и `risks.md`. Ниже — поля, которых
нигде в референсах нет по имени:

| Поле JSON | Что означает | Ось |
|---|---|---|
| `self_loops` | файлы, у которых ребро идёт само на себя (`f in graph[f]`); почти всегда артефакт разрешения импорта, не реальная самозависимость | structure |
| `type_only_edges` | число импортов, помеченных `type`-only (`TYPE_CHECKING`/`import type`) и исключённых из рантайм-графа `graph`, но видных в `graph_all` | structure |
| `barrels` | файлы-реэкспортёры (`__init__.py`, `index.ts`/`.js`/`.tsx`, `mod.rs`), за которыми скрыт реальный модуль-потребитель | structure |
| `adjacency` | полный список смежности рантайм-графа `{файл: [зависимости]}` — есть ли ребро импорта A→B, без grep | structure |
| `adjacency_through_barrels` | тот же граф, но рёбра в barrel развёрнуты до модуля за ним — иначе пара «сцеплены, но без импорта» ложно читается как R3 вместо R2 | structure |
| `layers_by_activity` | сколько коммитов затронуло каждый слой (`layer_of`), топ-15 — какие слои реально живут | behavior |
| `churn_profile` | разбивка правок по классам файлов `code`/`test`/`generated`/`noise` — вход калибровки, проверка «тесты отделены от кода» | behavior |
| `package_roots` | пакетные корни — угаданные (`guess_roots`) или заданные `--roots`; сегмент пути, отбрасываемый при определении слоя/резолве импорта; считают оба скрипта независимо | structure и behavior |
| `cycles_type_only` | SCC-циклы, существующие только через типовые рёбра `graph_all`; заведены нарочно, чтобы разорвать циклическую типизацию — не находка | structure |
| `hotspots[].fix_share` | доля коммитов-багфиксов среди правок файла (`fix_commits / edits`) — высокий, значит файл гниёт, не просто растёт | behavior |
| `cyclomatic_per_function_max` | максимум цикломатической сложности по одной функции файла (McCabe decisions+1); в отличие от `cyclomatic_total` сравним с порогом на функцию (см. врезку `risks.md`) | structure |

## 6. Правило

Ось намерения **никогда** не перебивает исполняемое поведение. Документ,
ADR, зелёный линтер — свидетельство того, что решили или заявили, не факт о
том, что происходит. При конфликте намерения и поведения фиксируется дрейф
(§3 artifacts.md); намерение не получает права переписать вывод `behavior.py`
или `structure.py` задним числом.
