## Вход и запуск

Вход: `/zodchiy refactor [путь] [--top N=1] [--dry] [--semgrep] [--lang ru|en]`.
Путь не задан — корень текущего репозитория. Цель — план упрощения кода по
измеренной простоте и лёгкости следующей правки, а не аудит: результат —
находки с пробой в изолированной копии.

Workflow принимает только путь, который вернул он сам, или файл из рабочего
каталога / добавленного каталога; `~/.claude/skills/…` ему не подходит.
Сначала скопируй `workflows/refactor.js` в scratchpad сессии (или в рабочий
каталог): `cp <skill>/workflows/refactor.js <scratchpad>/`. Затем вызови
Workflow: `scriptPath` — путь к этой копии (по умолчанию; `script` с
содержимым файла — только если копия невозможна), `args`:
`{repo, top, dry, semgrep, lang, skill, run_dir, date}`. `repo`, `skill`,
`run_dir` — абсолютные пути (`~` раскрой сам); `run_dir` —
`<repo>/.zodchiy/run-<YYYY-MM-DD>`, при втором прогоне в тот же день —
`run-<YYYY-MM-DD>-<HHMM>`: непустой `run_dir` Workflow не переиспользует, а
падает с его путём (стирать молча нельзя — там прошлые находки); `date` —
дата без времени. Умолчания только у `top` (1), `dry` (false), `semgrep`
(false), `lang` (`ru`).

## Команды режима

Полный путь: `python3 ~/.claude/skills/zodchiy/zodchiy.py <команда>`.

| Команда | Что делает |
|---|---|
| `lint <repo> [--measure <json>] [--semgrep]` | ruff-ось (`simplicity`, `width`, `perf`) и клоны — отладка; в `measure` то же лежит в `lint` |
| `slice --id F1 --measure <json> --findings <csv> --repo <repo> --out <json>` | срез `measure.json` под одну находку, ≤ 8192 байт; отброшенное считается числом |
| `trial prepare\|judge\|cleanup` (+ `discover`) | проба варианта в `git worktree`, ветка `zodchiy/F<n>-<slug>`; статус `accepted` / `rejected` / `unverified` решает код, не модель |
| `scribe --nonce <N> --run-dir <R>` | `decisions.json`, `refutation.json`, `findings.run.csv` из сохранённого промпта писаря; печатает отпечатки и `csv_ids` |
| `report --measure <json> --findings <json> --decisions <json> --format html\|md\|plan` | отчёт и план фаз из JSON; числа берутся из файлов, не из модели |
| `export --findings <csv> --measure <json> [--format sarif]` | находки машиночитаемо: JSON по схеме или SARIF; гоняет тот же `selfcheck` и отказывается собирать документ из брака |

## Роли

Каждая на явном ID модели; алиасы не используются.

| Роль | Модель · effort | Что делает |
|---|---|---|
| Замерщик | haiku · low | `measure` (в нём `lint` и `tools`) |
| Аналитик | opus · medium | карта, `findings.csv`, топ-N по приоритету |
| Критики L1, L2 | opus · high | линзы `references/refutation.md` по срезу |
| Критик L3 | opus · medium | то же, арифметика по кварталам уже в срезе |
| Проектировщики | opus · medium | вариант лечения: файлы, прогноз, `remedy_files` |
| Лид | opus · high | выбор, порядок, L4 (окупаемость) |
| Исполнитель | `sonnet-implementer` | правки в worktree выбранного варианта |
| Приёмка | `trial` (код) | `accepted` / `rejected` / `unverified` |
| Писарь | haiku · low | запускает `scribe`: файлы пишет код из сохранённого промпта, не модель; сценарий сверяет отпечаток FNV-1a |
| Отчётчик | haiku · low | `selfcheck`, `export`, `report` html / md / plan |

Агентам отдаётся `slice`, а не весь `measure.json`: он весит сотни килобайт.

## Отсечки

Отсечки — кодом сценария, не моделью.

- Находка со снятым возражением критика — без проектировщиков.
- `quick-fix` — один проектировщик с характером «удали, а не абстрагируй»,
  без лида; окупаемость судит `trial` по факту диффа. `scheduled` и
  `architectural` — три характера и лид.
- Характеры: «удали, а не абстрагируй», «минимальный интерфейс», «под
  реального частого вызывающего». «Максимальная гибкость» из
  `references/remedy.md` §2 здесь не используется: она противоречит метрике
  простоты.
- L4 («лечение дороже болезни») в этом режиме у лида, в `audit` — на шаге 4.
  Валюта — затронутые файлы; окупаемость выше порога (`PAYBACK_MAX_QUARTERS`,
  4, калибруется) → «знаем, не чиним»; боль 0 → «не чинить». Сценарий считает
  её кодом сразу после лида: `remedy_files` выбранного варианта ÷ боль среза,
  порог из среза; не `ok` — проба не запускается, находка в «Не входит». В
  отчёте это «прогноз лида», «факт пробы» появляется только у прошедших пробу.
- `architectural` идёт в пробу только первой фазой лида. Открытые
  `questions[]` лида — фаза в пробу не идёт.
- Порядок находок: расцепление раньше упрощения (`references/remedy.md` §5),
  затем риск, затем приоритет; `depends_on` не даёт зависимой встать раньше.
- Запасной вариант — одна попытка после `rejected` основного.
- `--dry` останавливается после лида и меняет только `.zodchiy/run-<дата>/`.

## Цена

Порядок величины для `--top 3 --dry` на репозитории с файлами в несколько
тысяч строк: 20–30 агентов, ≈12 мин, десятки млн токенов (основная часть —
чтение кэша, запись в кэш ≈1 млн), Opus ≈ 90 %. Точные цифры и даты прогонов здесь
не фиксируются: они протухают.

Resume сценария — не повтор: кэш по префиксу вызовов чувствителен к порядку,
pipeline перезапускает середину и может перевернуть вердикты критиков; фиксы
проверяй свежим прогоном.

## Проба

`trial` строит worktree от `HEAD`, в основное дерево не пишет и ничего не
мержит. Ветка `zodchiy/F<n>-<slug>`; занята — суффикс `-2`, факт пишется в
`decisions.json`. Незакоммиченное в пробу не попадает: `base_dirty`, отчёт это
показывает. Проверки проекта идут списком, по одной; нет тестов (линтер и
`ruff F821` тестами не считаются), таймаут или нет Docker — `unverified` с
причиной, а не «красный».
У architectural проба — только первая фаза, а цель `gain` задана на всю находку:
промах по ней после фазы даёт `unverified` («фаза 1 из N…»), не `rejected`.

## Выход

`plan.md` пишется только в `.zodchiy/run-<дата>/`; `report.html` и `report.md` —
там же. Шаги, прогноз и риск плана — из варианта, который лежит в ветке
(`trial.variant`; запасной после отказа основному), без пробы — выбранного
лидом (`decisions.json`); remedy аналитика — только если варианта нет. Отчёт
показывает `run.skipped` — находки, упавшие на этапе или снятые критиком, с
причиной. Ничего не срезается молча: отсечка аналитика (`run.candidates`:
кандидатов, взято, отброшено) и ненулевые `*_dropped` среза по каждой находке
(`slice_dropped`) идут в отчёт числами.

## После Workflow — шаги главной сессии

1. Ответ Workflow: `errors` непуст или `report_html: null` — сказать об этом
   вслух и назвать причину; отчёта нет, делать вид, что он есть, нельзя.
2. Скопировать `report.html` в корень `~/Downloads` и отдать через
   `SendUserFile` (путь без кириллицы).
3. Проверить, что `.zodchiy/` есть в `.gitignore` проекта. Нет — сказать
   Ивану, молча не дописывать.
4. `plan.md` предложить скопировать в
   `.claude/specs/<дата>-code-simplification.md` проекта; без согласия
   не копировать. План не коммитится: путь должен быть в `.gitignore`
   проекта, иначе сказать Ивану.
5. В чат — пять строк: штамп (репо, `HEAD`, дата, потолок, число агентов);
   сколько находок взято, сколько отброшено, сколько пропущено; вердикт по
   каждой (принята / отклонена / не проверена, прогноз против факта); ветки
   `zodchiy/F<n>-…` с командой `git diff <база>...<ветка>`; пути отчёта и плана.

Ветки принятых проб остаются в репозитории, мерж — за Иваном.
